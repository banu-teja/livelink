## 2024-05-15 - [CSWSH] Cross-Site WebSocket Hijacking Prevention
**Vulnerability:** The custom WebSocket server implementation (`process_request` using `websockets` library) did not validate the `Origin` header for incoming connection requests. This could allow an attacker on an external domain to initiate a WebSocket connection to the server on behalf of a victim user (Cross-Site WebSocket Hijacking).
**Learning:** When manually managing WebSocket HTTP handshakes using `websockets.asyncio.server.serve(process_request=...)`, `websockets` does not enforce Origin checks automatically by default in all configurations unless explicitly checked or strict CORS logic is implemented. If CORS is disabled (or not strictly enforcing same-origin), it opens up CSWSH.
**Prevention:** Explicitly validate the `Origin` header during the HTTP upgrade request against the expected `Host` or `X-Forwarded-Host` headers to enforce same-origin policy for WebSocket connections when CORS is disabled. Always block mismatched origins with a 403 Forbidden response.
