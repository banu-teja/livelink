## 2024-11-09 - Cross-Site WebSocket Hijacking (CSWSH) Prevention
**Vulnerability:** The `agent.serve()` WebSocket handler lacked `Origin` header validation when processing new connection requests, making the endpoint vulnerable to Cross-Site WebSocket Hijacking (CSWSH). If `cors` was disabled, it implicitly allowed cross-origin connections to upgrade successfully.
**Learning:** In the `websockets` library, if `process_request` returns `None`, the handshake proceeds. To enforce fail-closed security, any unhandled validation checks, parsing exceptions (e.g., from `urllib.parse`), or missing headers should explicitly return an `http11.Response` object (such as a 403 Forbidden). Also, `urllib.parse.urlparse().hostname` drops the brackets for IPv6 hosts, requiring manual reconstruction to match standard host headers safely.
**Prevention:** Ensure all custom WebSocket connection processors manually enforce `Origin` versus `Host`/`X-Forwarded-Host` validation when CORS is disabled. Implement robust fail-closed exception handling (`# noqa: BLE001` to safely swallow explicit security rejection paths) during header parsing.
