## 2025-02-14 - Fix Cross-Site WebSocket Hijacking (CSWSH) in serve.py
**Vulnerability:** The default `agent.serve()` WebSocket handler did not validate the `Origin` header during the handshake. This allowed any arbitrary origin (like an attacker's website) to connect to the agent server (`ws://localhost:8000/`) within the local environment or on a public instance and interact with the AI assistant seamlessly.
**Learning:** `websockets` library does not automatically perform `Origin` matching when handling manual routing via `process_request` with an HTTP 101 switch. When exposing a local server to browser connections, explicitly verifying that `Origin` matches `Host` is critical to prevent cross-site connection hijacking.
**Prevention:** Always validate the `Origin` header against the expected `Host` during the WebSocket HTTP handshake if CORS is disabled. If `Origin` doesn't match the `Host`, explicitly return an HTTP 403 Forbidden response before allowing the upgrade.
