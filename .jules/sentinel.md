## 2024-11-03 - Cross-Site WebSocket Hijacking (CSWSH) in WebSocket Server
**Vulnerability:** The custom WebSocket server (`serve()` in `src/livelink/serve.py`) does not validate the `Origin` header against the `Host` or `X-Forwarded-Host` header during the handshake (`process_request`).
**Learning:** Bypassing standard frameworks and handling raw WebSockets means you must manually implement CSWSH protections, otherwise malicious sites can open WebSocket connections to the local server on behalf of a user. Furthermore, the `websockets` library expects `process_request` to return `None` to allow a connection, or an `http11.Response` to reject it. Also, IPv6 hostnames contain brackets which `urllib.parse` strips out, so they must be carefully checked when comparing against the `Host` header.
**Prevention:** Implement an explicit `Origin` vs `Host` validation in `process_request` when `cors` is disabled. Any mismatch or parsing error should fail closed (return a 403 response).
