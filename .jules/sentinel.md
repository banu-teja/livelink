## 2024-05-24 - [CRITICAL] Cross-Site WebSocket Hijacking (CSWSH) in serve.py
**Vulnerability:** The built-in WebSocket server (`serve.py`) did not validate the `Origin` header during the WebSocket handshake when `cors` was disabled. Browsers always send the `Origin` header for WebSocket connections, and `websockets` allows all origins by default. This allowed a malicious website to open a connection to the locally running `livelink` agent and interact with it, hijacking the user's voice AI agent and potentially executing tools on their machine using their API credentials.
**Learning:** WebSockets do not respect CORS restrictions by default. Even if `cors=False` is set to prevent cross-origin requests, `websockets` will still allow cross-origin WebSocket connections unless the `Origin` header is explicitly validated in the handshake (e.g., in `process_request`).
**Prevention:** Always validate the `Origin` header in the `process_request` hook of the `websockets` library. If `cors=False`, explicitly reject requests where the `Origin` does not match the server's expected host/port.
