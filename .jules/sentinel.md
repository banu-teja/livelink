## 2024-05-18 - [Security Headers on Upgrade Endpoints]
**Vulnerability:** Missing security headers (`Content-Security-Policy`, `X-Content-Type-Options`, `X-Frame-Options`) on HTTP responses from the WebSocket upgrade handler and the default UI endpoint in `livelink/serve.py`.
**Learning:** Even though the primary interface is a WebSocket, the initial HTTP handshake and the built-in HTML UI endpoints are vulnerable if they don't explicitly declare security boundaries. Without headers like CSP and X-Frame-Options, an application using `livelink.serve` could be subjected to MIME sniffing or clickjacking attacks, especially when served on default or shared ports.
**Prevention:** Always inject standard security headers (CSP, nosniff, DENY framing) during the HTTP phase of any WebSocket server or built-in UI handler. Ensure `Content-Security-Policy` explicitly permits only the expected `ws:` / `wss:` connections to prevent XSS-driven data exfiltration to unauthorized endpoints.
