## 2025-02-27 - Cross-Site WebSocket Hijacking (CSWSH) in WebSocket Server
**Vulnerability:** The built-in WebSocket server in `livelink/serve.py` does not validate the `Origin` header during the WebSocket handshake when `cors` is `False`. This allows any external website to establish a WebSocket connection to the local server, potentially interacting with the agent or hijacking the session.
**Learning:** WebSocket connections are not protected by the Same-Origin Policy (SOP) by default. Without an explicit `Origin` check during the handshake, a malicious site visited by a user can connect to `ws://localhost:8000` (or wherever the server is hosted) and bypass standard cross-origin restrictions. The `cors` flag was only controlling the `Access-Control-Allow-Origin` header for HTTP responses, but did not protect the WebSocket upgrade endpoint itself.
**Prevention:** Always validate the `Origin` header against an allowed list or the `Host` header during the WebSocket handshake `process_request` hook, especially for applications serving local agents where `localhost` binding is common.
