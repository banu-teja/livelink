## 2024-11-10 - Cross-Site WebSocket Hijacking (CSWSH) in serve.py
**Vulnerability:** The WebSocket server in `src/livelink/serve.py` accepted connections without validating the `Origin` header, allowing malicious websites to initiate Cross-Site WebSocket Hijacking (CSWSH) attacks when CORS is disabled.
**Learning:** For WebSocket connections, the `Origin` header must be validated against the `Host` or `X-Forwarded-Host` header to ensure the request is not originating from an unauthorized cross-origin site when `cors=False`. This is because standard browser CORS policies do not apply to WebSocket handshakes in the same way they do to HTTP requests. Also learned that when validating the `Origin` header we must fail-closed and reject the connection if parsing errors occur.
**Prevention:** Always validate the `Origin` header during WebSocket connection handshakes if CORS should be restricted. Catch all exceptions during parsing (fail-closed) and gracefully handle IPv6 hostnames (bracketed IPs).
