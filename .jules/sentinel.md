## 2023-10-25 - Prevent CSWSH by Validating Origin on WebSockets
**Vulnerability:** Cross-Site WebSocket Hijacking (CSWSH) potential in `agent.serve()` when `cors=False`. The `websockets` server implementation defaults to accepting connections from any origin unless explicit validation is implemented in the `process_request` hook or via an `origins` argument.
**Learning:** Custom implementations of `process_request` on `websockets` must explicitly include an `Origin` vs `Host` check; relying on the absence of CORS HTTP headers is insufficient, as modern browsers only block HTTP requests based on CORS policies but will allow WebSocket upgrades (`ws:`) regardless, provided the origin is simply passed in the `Origin` header. Thus, the server itself must enforce the `Origin`.
**Prevention:** Always implement `Origin` validation in WebSocket upgrade handlers or utilize the `origins` parameter in the `websockets.serve()` handler to deny unauthorized cross-origin requests when CORS is disabled.
