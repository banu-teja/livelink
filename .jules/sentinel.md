## 2025-02-23 - [Cross-Site WebSocket Hijacking (CSWSH) Protection]
**Vulnerability:** The custom WebSocket server implementation (`serve.py`) lacked `Origin` validation, making it susceptible to Cross-Site WebSocket Hijacking (CSWSH) when CORS was implicitly or explicitly disabled.
**Learning:** `urllib.parse.urlparse().hostname` correctly parses hostnames but intrinsically drops surrounding brackets for IPv6 addresses (e.g., `[::1]` becomes `::1`). If these are compared against raw header values strings or reconstructed inconsistently, the validation can bypass legitimately or fail open. Additionally, handling manual HTTP upgrades in `websockets` requires a fail-closed response pattern: returning a 403 `http11.Response` on exception parsing.
**Prevention:** Always compare normalized and bracketed IPv6 string representations. Catch generic exceptions (`Exception`) when parsing input headers for security enforcement and intentionally fail closed (suppress linter warnings with `# noqa: BLE001` if necessary). Ensure that `Origin` validation strictly occurs when CORS is explicitly disabled.
